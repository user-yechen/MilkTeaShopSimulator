## 0. 怎么用这份文档

- 按模块找类 → 看公开字段/方法 → 看它被谁调用（第 3、5 节）
- `public` 才是对外接口；`private` 只写进「关键流程」帮助理解，不要从外部调用
- 签名里的 `= 默认值` 是 Inspector 默认值，改之前确认没有场景覆盖
- 标 **AutoAttach** 的类不需要手动挂，运行时自动加到符合条件的物体上

## 1. 全局约定

| 约定 | 说明 |
|---|---|
| 单例 | `GameClock.Instance`、`ShopManager.Instance`、`CupInteract.Instance`，`Awake` 赋值 |
| 自动挂载 | `[RuntimeInitializeOnLoadMethod(AfterSceneLoad)]` + 按名字/子节点特征查找 |
| 事件 | `GameClock.OnNewDay`、`PasserbyWalk.OnArrivedAtCounter/OnLeft`、`MachineLevel.OnLevelChanged` |
| 存档 | 只有 `GameClock` 写盘；其它系统通过 `GameClock.Instance.SaveTime()` 间接触发 |
| UI 查找 | 大量按物体名查找（`金额`/`营收额`/`台面`…），**改名会静默失效** |
| 静态工具 | `CupInteract.ToLocalScale`、`MachineLevel.CanonicalIdFor`、`ModelScaler.*` 纯函数，可直接调 |

## 3. 关键调用链

### 3.1 取杯 → 注液 → 加热 → 上台

```
CupInteract.OnGetMedium()                 // 杯架按钮
  └─ PickUpFromRack(mediumContainer, Medium)
       ├─ Instantiate 杯模板
       ├─ AddComponent<Cup>()  → 立刻 Awake
       └─ cupType = Medium（赋值在 AddComponent 之后）

CupInteract.OnInject()                    // 「放入奶茶杯」
  └─ TeaMachine.PlaceCup(cup)             // 摆到杯位，记录 worldScale

FluidCellButton.onClick                   // 交互界面里的「牛奶/茶」格子
  └─ TeaMachine.PourColored(color, label)
       ├─ TryConsume(label, 大杯500/中杯300)
       ├─ PourFluid.Spawn(nozzle, color)
       ├─ Cup.SetLiquidColor(color, forceOpaque)
       ├─ Cup.AnimateFill(0.70, duration)
       └─ Cup.teaType = label

CupInteract.OnHeat()                      // 「加热」
  └─ HeaterMachine.PlaceCup(cup)          // 优先空位，SetTemperature(Hot)

CupInteract.OnPlaceOnCounter()            // 「放到前台」
  └─ CounterCupDisplay.TryPlaceCup(cup)   // 复制一份展示，原杯销毁
```

### 3.2 顾客点单 → 交付 → 结算

```
PasserbyWalk（State.WalkingIn → Ordering）
  ├─ 到达前台：OnArrivedAtCounter
  │    └─ OrderBubble.ShowSequentially()   // 气泡+图标逐个显示
  ├─ 等待符合订单的成品
  │    └─ CounterCupDisplay.HasCup(type, teaType)
  ├─ 取走：CounterCupDisplay.TakeCup(type, teaType)
  │    └─ ShopManager.CompleteOrder()      // 营收 += 10 + 随机小费
  └─ 离店：OnLeft → OrderBubble.Hide()
```

### 3.3 打烊 / 第二天

```
ShopManager.Update()
  └─ clock.IsAtOrAfter(16:00) → EndDay()
       ├─ clock.enabled = false
       ├─ clock.AddToWallet(Revenue)       // 立即存档
       └─ 结束面板「今日营收：X 元 / 钱包：Y 元」

「再玩一次」→ ShopManager.RestartDay()
  ├─ Revenue = 0
  ├─ GameClock.NextDay(8, 0)              // Day++ → 存盘 → OnNewDay
  ├─ 清空前台杯子
  └─ PasserbyWalk.RestartDay()
```

### 3.4 存档

```
GameClock.SaveTime()  →  GameTimeStore.Save(day, wallet)   // JSON 覆盖写
MachineLevel.SetLevel() → GameTimeStore.SetMachineLevel()  // 内部仍走 GameClock.SaveTime()
启动：GameClock.Start() → GameTimeStore.Load() → 恢复天数/钱包/钟点
```

### 3.5 商店购买 / 升级

```
ShopItem 点击
  ├─ IsOwned（GameTimeStore.GetMachineLevel(id) >= itemLevel）→ 提示
  ├─ 余额不足 → 提示
  └─ ShopPurchaseDialog.ShowConfirm
       └─ 确认 → GameClock.TrySpend(price)
                 → MachineLevel.SetLevel(id, itemLevel)
                 → ShopItem.RefreshAll()
```

**改动影响面速查**

| 你改了 | 会影响到 |
|---|---|
| `Cup` 的杯型/温度枚举 | CupInteract、TeaMachine、HeaterMachine、CounterCupDisplay、OrderBubble |

| 场景物体改名（营收额/台面/杯位…） | 对应脚本按名字查找会静默失效 |

## 6. 命名与新增接口的约定

1. 新的玩家交互按钮一律走 `CupInteract.AddSharedButton(label)`，不要自建屏幕按钮
2. 新设备实现 `IsNear / PlaceCup / TakeCup` 三件套，再在 `CupInteract` 里加转发
3. 新存档字段加到 `GameTimeData`，并写迁移兜底（缺字段用默认值）
4. 新 UI 面板提供 `PanelCloseButton`，`windowRoot` 指到根节点
5. 对外只暴露必要方法；`private` 方法不要跨类调用（本项目已按此拆分）
6. 改任何 `public` 签名后，全局搜索调用点并更新本文

## 8. 实现备注（易踩坑，迁移自旧上下文）

1. **AddComponent 立刻 Awake**：`PickUpFromRack` 先 `AddComponent<Cup>()` 再赋 `cupType`，
   所以 `Cup` 的初始化必须惰性化，不能依赖 `Awake` 里的 `cupType`。
2. **同名「金额」**：营收面板和钱包面板的数值 Text 都叫「金额」，必须按面板子树查找
   （`FindStatText(panelName, "金额")`），全局查找会拿错。
3. **出料口会丢**：换模型后场景没有「出料口」节点时，`TeaMachine` 会在杯位正上方 0.5 m
   自动建「出料口(自动)」保住出液动画；要精确控制就手动建同名子物体。
4. **杯子烘焙网格 Y 镜像**：杯口在 local -Y，手持/上机统一 X 旋转 180° 翻正
   （`CupInteract.heldCupEuler = (180,0,0)`）。
5. **杯架每容器只有第 0 个子物体是真杯**：其余是空 `(Clone)` 占位；杯子上没有 `Cup` 组件，
   运行时才 `AddComponent`。
6. **交互按钮只有一个入口**：所有玩家交互按钮走 `CupInteract.AddSharedButton(label)`；
   `ShelfInteract` / `MachineRefillInteract` 已删掉自建按钮的兜底，`Instance` 为空就本帧跳过。
7. **Resources 路径要带前缀**：预制件在 `Assets/Resources/预制件/`，加载写
   `Resources.Load("预制件/XXX")`，少一层会拿到 null。
8. **改名会静默失效**：大量逻辑按物体名查找（`营收额` / `钱包` / `金额` / `台面` / `杯位` /
   `提示框` / `左上角UI`），改名后不报错但功能消失。
9. **粒子只拷 position**：`PourFluid` 不要继承 nozzle 的旋转，否则 Shape 旋转叠加会喷错方向。
10. **预制件变体引用**：YAML 里不能手填 `100100000` 当根 GameObject 引用（会解析成 PrefabInstance，
    `Instantiate` 抛 `InvalidCastException`）；要在 Inspector 拖。
11. **UGUI 锚点**：`anchor(0.5,1)` 时 `anchoredPosition.y` 为正会出屏，往下填负数。
12. **液体参数写死**：大杯 `liquidLocalY = -0.25`、中杯用 `cupMinY`，都是手动反算的结果，
    不要改成统一公式（运行时 `cupMinY` 与网格推算值不一致）。

## 9. 文案接口（GText）

> 运行时 `Assets/脚本/文案/GText.cs`；文案数据 `Assets/Resources/文案/文案表.csv`；
> 常量 `Assets/脚本/文案/GTextKeys.cs`（自动生成，勿手改）。

### 9.1 运行时 API

```csharp
public static class GText
{
    public static string Get(string key, string fallback = null);   // 取文案，缺失时警告并返回 key
    public static string Format(string key, params object[] args);  // 带 {0} {1} 占位符
    public static bool Has(string key);                             // 是否有该 key
    public static void Reload();                                    // 强制重载 CSV
    public static int Count { get; }                                // 条目数
}
```

用法：

```csharp
label.text = GText.Get(GTextKeys.UiShopTitle);            // 编译期常量，防拼错
body.text = GText.Format(GTextKeys.UiDayEndBody, revenue, wallet);
```

### 9.2 CSV 列

`key, category, zh, en, speaker, maxChars, note`

- `key`：全局唯一，`模块.对象.字段`
- `zh`：中文；换行写 `\n` 两个字符，运行时自动转换
- `maxChars`：校验用字数上限

### 9.3 校验与生成

- 菜单 **奶茶店/文案/校验并生成 Key**：查重复 key、非法格式、空文案、超字数、常量名冲突，
  通过后重写 `GTextKeys.cs`
- 命令行：`-executeMethod TextImportTool.ImportForCI`（失败退出码 1）
- 自检：`-executeMethod TextImportTool.SmokeTest`（打印 key 数与示例）
