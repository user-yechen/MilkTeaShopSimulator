# 奶茶店模拟器 · 产线缺口与待办清单

> 更新时间：2026-11-27　｜　用途：作为项目负责人的「还差什么才能上线」总表。
> 用法：P0 → P3 顺序推进，勾选即完成；每周把「本周完成」同步回 `文档/上下文.txt`。

---

## 一、现状判断（一句话）

项目已经是一个**可玩的垂直切片**：进店寻路 → 前台点单 → 取杯 → 奶茶机注液 → 加热/加冰 → 交付 → 营收 → 16:00 打烊结算 → 存档 → 次日 → 商店升级骨架。
工程上也有雏形：价格表外置、通用等级组件、升级换模缩放、40+ 编辑器菜单、上下文持久化文件。

但离「能交付的产品」还差 5 层：**出包工程、玩法深度、内容量、体验层、发行合规**。

## 二、已验证的硬缺口（带证据）

| # | 缺口 | 现状证据 | 影响 | 优先级 |
|---|------|----------|------|--------|
| 1 | 打不出包 | `ProjectSettings/EditorBuildSettings.asset` 的 `m_Scenes: []` 为空 | 现在根本构建不出可运行版本 | P0 |
| 2 | 无版本控制 | 项目根无 `.git`、无 `.gitignore` | 一次误删/改崩无法回滚；Library/obj 混在工程里 | P0 |
| 3 | 无任何音频 | 全部运行时脚本 0 处 `AudioSource` / `AudioClip` | 成品感为零，动作全哑 | P0（资源）/P2（体验） |
| 4 | 无中文字体资产 | `Assets` 下 0 个 `.ttf/.otf`，UI 走 LegacyRuntime 动态字体 | 真机可能缺字/方块、字形不统一 | P1 |
| 5 | 无启动/暂停/退出流程 | 只有一个场景；设置面板「退出游戏」未接线 | 产品无法正常开始、暂停、退出 | P1 |
| 6 | 订单只有 2 个槽位 | `OrderBubble` 只随机杯型 + 固定「牛奶」；温度/配料/盖料是注释里的 TODO | 玩法单薄，5 分钟就腻 | P1 |
| 7 | 无顾客压力 | 同一时刻仅 1 位路人，无排队、无耐心条、无流失 | 没有挑战，也没有失败 | P1 |
| 8 | 收益与订单无关 | `ShopManager.CompleteOrder` 固定 `10 + Random(1,5)` | 做对做错一个样，技巧无价值 | P1 |
| 9 | 升级只写等级 | `ShopItem` 购买只 `MachineLevel.SetLevel`；`ModelScaler.UpgradeReplace` 未接；除冰格外无效果 | 花钱没有可见回报，成长感缺失 | P1 |
| 10 | 无新手引导 | 首次进入无任何提示 | 玩家不知道「取杯→注液→加热→交付」顺序 | P1 |

| 14 | 合规空白 | `companyName="123"`、包名未定、无隐私政策/首启同意/SDK 清单/版号计划 | 无法上架；国内商业化有法律风险 | P3（要提前启动） |

## 三、P0：让项目「能出包、能回滚」（3–5 天）

**目标：任何人拿到仓库，一条命令出一版可安装包，并能回到任何一个历史版本。**

- [ ] **版本控制**
  - `git init`；写 `.gitignore`（`Library/ Temp/ Obj/ Logs/ UserSettings/ Build/ .vs/ *.csproj *.sln`，但 `Assets/ ProjectSettings/ Packages/` 必须进库）
  - 配 Git LFS：`*.glb *.fbx *.png *.psd *.wav *.mp3 *.blend`
  - `git add -A && git commit -m "baseline: 垂直切片"`；打 tag `v0.0.1-slice`
  - 远端仓库（GitHub/Gitee/自建）；之后**每完成一个功能就提交**，大改前开分支
- [ ] **修复构建**
  - Build Settings 加入 `Assets/Scenes/奶茶店.unity`（`SampleScene` 移出或删除）
  - `PlayerSettings` 正式化：公司名/产品名、`applicationIdentifier`（如 `com.你的工作室.milktea`）、`bundleVersion=0.1.0`、横屏锁定、Android 最低 API 24、目标 API 按渠道当年要求、ARM64 + IL2CPP
  - 应用图标、启动图（Splash）、默认光标/分辨率
- [ ] **一键出包脚本** `Assets/Editor/BuildScript.cs`
  - 菜单「奶茶店/构建/Android APK」+ 命令行 `-executeMethod BuildScript.BuildAndroid`
  - 产物 `Build/Android/milktea_0.1.0_{yyyyMMdd_HHmm}.apk` + 构建日志；失败返回非 0
- [ ] **真机基线**
  - 一台低端安卓 + 一台中端机跑通完整一天（8:00→16:00）
  - 记录：平均 FPS、最差帧、内存峰值、发热、启动耗时，写进 `文档/性能基线.md`
- [ ] **存档兜底**
  - `gameTime.json` 加 `version` 字段与读取失败兜底（损坏→备份旧档→重建）
  - 设置面板加「重置存档」二次确认（QA 与玩家都需要）

**验收：** 新克隆仓库 → 打开工程 → 菜单一键出 APK → 安装可玩完整一天 → 崩溃后重进不丢档。

## 四、P1：让玩法「成立」（1–2 周）

**目标：有目标、有压力、有反馈、有成长，玩家能连续玩 30 分钟。**

### 4.1 订单系统数据化
- [ ] 新建 `OrderDefinition`（ScriptableObject 或 JSON）：杯型 / 液体 / 温度 / 配料 / 盖料 + 权重 + 解锁天数 + 基础价
- [ ] `OrderBubble` 改为数据驱动：槽位图标通用化，图标放 `Resources/贴图/订单图标/`，缺图只警告不崩
- [ ] 温度：热 / 正常冰 / 少冰 / 去冰（复用 `Cup.Temperature` 与加热机、冰格）
- [ ] 配料：珍珠 / 椰果 / 奶盖（先做 1–2 种，有可见小料模型或杯内色块）
- [ ] 盖料：封口/加盖（可先只做「必须盖盖」一个动作）

### 4.2 制作与校验闭环
- [ ] 交付校验扩到全部槽位（现在只比杯型 + 液体）
- [ ] **不匹配要给反馈**：现在不匹配就静默继续等，玩家不知道为什么 → 显示「顾客要的是热的大杯珍珠奶茶」提示
- [ ] 做错可撤：倒掉重做（垃圾桶/水槽），有成本但不卡死
- [ ] 制作动作补全：取杯→注液→加料→加热/加冰→封盖→交付，每步有按钮与状态

### 4.3 顾客与压力
- [ ] 支持 2–4 位顾客同时在场（排队位/等候区）
- [ ] 耐心条：等待超时离店，扣评价/断连击
- [ ] 顾客类型：学生/上班族/外卖员（点单复杂度与客单价不同）
- [ ] 到店节奏随天数/等级加快，形成难度曲线
- [ ] 评价系统：单日星级 → 影响次日客流与单价

### 4.4 经济与成长
- [ ] 收入公式：`订单基础价（按配方） + 小费（按剩余耐心） - 原料成本`
- [ ] 升级树：奶茶机（出液速度/容量）、加热机（加热速度/双杯）、制冰机（冰量）、货架（容量/自动补货）、前台（排队位/收银速度）
  - 每级有**数值效果**，不只是解锁按钮
  - 购买后接 `ModelScaler.UpgradeReplace` 换模型（`Resources/预制件/前制作台lv1~lv3` 已有，先拿它打通一条）
- [ ] 每日目标：营业额目标 + 连续达标天数奖励
- [ ] 打烊结算升级：营收/成本/小费/差评明细 + 今日评级 + 钱包变化动画

### 4.5 引导与首启
- [ ] 首启 3 步引导：取杯 → 注液 → 交付（高亮 + 手指 + 一句文案），可跳过
- [ ] 引导完成奖励（一小笔启动资金），避免开局没事干
- [ ] 设置面板补：音乐/音效音量、画质档、语言（若多语言）、重置存档、退出游戏

### 4.6 存档扩展
- [ ] `GameTimeData` 扩：设置、统计（总营业额/总顾客数/最高连击）、已解锁配方、当日进度
- [ ] 存档带版本号 + 迁移函数；测试「旧档升级不丢数据」

**验收：** 连续玩 3 个游戏日不崩；做错单有明确提示；升级后能感知速度/容量变化；新玩家不看文档能完成第一单。

## 五、P2：让体验「像成品」（2–3 周）

### 5.1 音频（当前完全空白）
- [ ] BGM：白天营业 1 首 + 打烊/夜晚 1 首（循环、淡入淡出）
- [ ] 环境音：店内空调/街外人群，音量低于 BGM
- [ ] SFX 清单：脚步、开门铃、取杯、出液、加热、加冰、封盖、收银、按钮、好评、差评、硬币
- [ ] `AudioManager` + Mixer 分组（Master/BGM/SFX），音量存 PlayerPrefs 并接设置面板
- [ ] 首次点击/触摸后再播 BGM（移动端音频解锁）

### 5.2 UI / UX
- [ ] CanvasScaler 改 `match=0.5`，按 16:9 设计，验证 4:3 / 20:9 / 平板
- [ ] `SafeArea` 组件包住 HUD 与按钮
- [ ] 引入 **TextMeshPro + 中文 SDF 字体**（思源黑体/Noto Sans SC，常用字子集），全量替换 Legacy Text
- [ ] 按钮命中区 ≥ 44×44 px；所有可点元素有按下态/禁用态
- [ ] 面板统一动效（缩放/淡入 0.15–0.2s），数字滚动
- [ ] 交互按钮（滚动视图那套）加图标与冷却态
- [ ] 加载/转场：进场景黑屏淡入、打烊渐暗
- [ ] 返回键（Android）逐级关闭面板，最后确认退出

### 5.3 美术与内容量
- [ ] 风格统一：材质/贴图分辨率/描边规范，写 `文档/美术规范.md`
- [ ] 店铺可读性：招牌、菜单板、价目牌、灯箱、地面分区
- [ ] 装饰/家具 3–5 件可购买摆放（先固定点位，不做自由摆放）
- [ ] 顾客模型 2–3 个变体（换色/换配件即可）
- [ ] 配方内容：至少 6–8 款饮品（奶茶/果茶/热饮/冰沙），每款有图标与价格
- [ ] 动画：顾客取餐/交付手部动作、封盖、杯内液体晃动（可选）
- [ ] 粒子：出液已有；补热气、冰雾、收银星星

### 5.4 性能
- [ ] 灯光烘焙（Baked/Mixed），去掉每块天花板一个实时点光；移动端目标 ≤2 个实时灯
- [ ] 静态合批 / GPU Instancing 检查；DrawCall 目标 < 150
- [ ] 纹理压缩 ASTC（6x6/8x8），图集合并 UI 图
- [ ] 对象池：顾客、杯子、订单图标、飘字
- [ ] 帧率目标：低端 30fps、中端 60fps；加帧率显示开关（开发版）
- [ ] 启动时间 < 5s（中端机）

**验收：** 静音玩和开声音玩是两种体验；低端机稳定 30fps；中文在任何机型无方块；20:9 全屏无遮挡。

## 十、范围控制（先砍什么）

**MVP 定义（建议）**
- 1 家店、1 个场景、6 款饮品、3 类顾客、10 项升级、7 天循环、单局 20–30 分钟

**第一版明确不做**
- 多店铺/连锁经营、多人联机、剧情线、天气与季节、自由摆放家具、成就系统、排行榜、云存档、多语言（除非要出海）

**判断标准**
> 每加一个功能，问：它是否让「取杯→制作→交付→收钱」这个循环更好玩？
> 否 → 放进 v1.1 清单，不进这一版。

## 十二、本周就能做的 10 件事（按顺序）

1. `git init` + `.gitignore` + 首次提交（半天）
2. Build Settings 加场景，出一版 APK 装到手机（半天）
3. 写 `BuildScript.cs` 一键出包（半天）
4. 真机跑完整一天，记 FPS/内存/发热（半天）
5. 引入 TMP + 思源黑体，替换一处 UI 验证中文（1 天）
