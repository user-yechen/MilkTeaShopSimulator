① PasserbyWalk.cs —— 路人 AI。状态机 WalkingIn→Ordering→WalkingOut→Finished 循环。

   RestartDay() 清零；RuntimeInitializeOnLoadMethod 自动挂名字含"路人"的物体。

② ShopManager.cs —— 营业/营收/结束面板。8:00→16:00；CompleteOrder += 10+Random.Range(1,5)；16:00 弹结束面板。

⑨ Cup.cs —— 杯子组件（运行时才 AddComponent，预制体上没有）。CupType{Medium,Large} / Temperature{RoomTemp,LessIce,NoIce,NormalIce,Hot}；

   中杯 底r=0.07215 斜率=0.229354 满高=0.46215 liquidLocalY=cupMinY。公式：height=满高×fill；topR=底r+斜率×height。
   实测：大杯网格(guid 8e40283a) bounds y∈[-0.4272,0.3607] 高 0.7879，运行时 cupMinY≈-0.0665（=网格 min+maxY）；中杯(guid c25de16e) y∈[-0.2463,0.2157] 高 0.4621。
   **两张烘焙网格均 Y 镜像（杯口在 local -Y）** → 手持/上机统一 X 旋转 180° 翻正。

【历史经验教训】
================================================================

1. 场景中文 YAML 存 \uXXXX，grep 搜不到，要 python unicode_escape 解码
2. csc 验证引用：facade（Managed\UnityEngine.dll / UnityEditor.dll / Managed\UnityEngine\UnityEditor.dll）与模块 DLL 不可混用——完整可用组合见【项目元信息】
3. ApplyScaleTool 累积变换用 Matrix4x4，别 Quaternion+Vector3 分开（非均匀缩放×旋转不可交换）
4. BoxCollider 无法表示旋转，近似用三轴向量长度换算 size
5. 地面检测先过滤 IsChildOf(transform) 的自身 Collider
6. 新节点未 Ctrl+S → 磁盘场景查不到（FindSlot/名字查找失败先怀疑没保存）
7. ParticleSystem Shape 局部旋转×LocalSimulationSpace：SetParent 继承 nozzle 旋转 + gravity 世界坐标会错位；修：只拷 position
8. Cone 默认 local+Z 发射，绕 X 轴 +90° 向下落水，-90° 向上喷泉
9. StartsWith 名字歧义："奶茶杯_中" 会匹配 "奶茶杯_中(Clone)"；模板用名「中奶茶杯」避开
10. m_LocalEulerAnglesHint 是 Editor 显示缓存，真实旋转看 m_LocalRotation 四元数
11. 重构原则：状态+行为下沉到设备组件，协调器只做"谁在近处+弹按钮+转发"
12. 设备 GameObject 名不可靠（可能用别的 Prefab 搭）→ AutoAttach 用子节点特征反查（「杯位」/「出料口」）
13. C# 元组解构：var (cup, scale) = TakeCup(...) 直接可用
14. JSON 存档：JsonUtility+persistentDataPath 即可；恢复放 Start 不放 Awake（保证 ShopManager.Instance 已初始化）
15. UI 挂点优先用场景已有节点改内容，别 new 组件覆盖用户美术排版
16. 液面/包围盒：①Renderer.bounds 是世界 AABB，物体旋转会膨胀/错位 → 用网格本地包围盒角点换算；②Mesh 顶点含 baseY 时 localPosition 别再叠偏移；③CupMeasureTool 底部分带平均半径对锥形杯偏低
17. UGUI：anchor(0.5,1) 时 anchoredPosition +y 向上出屏，往下填负数；pivot(0.5,1)+y=0 才贴屏幕顶；Scene 视图按参考尺寸居中，可见性以 Game 视图/Canvas 尺寸算
18. AddComponent 立刻执行 Awake：随后才赋的字段 Awake 里读的是默认值 → 初始化惰性化（用时按当前值重算），或先 SetActive(false) 挂组件赋值后再激活
19. 杯架杯子=GLB 实例+m_Mesh 烘焙网格覆盖，不是 wrapper 预制体；「原生大小」烘焙网格 Y 镜像（杯口在 local -Y），统一 X 180° 翻正
20. 手动微调的液体 Transform 反算参数：Y 缩放 sy→高×sy 斜率÷sy；等比 s→底 r×s 斜率不变；位置直接写死 liquidLocalY 绝对值，别用 cupMinY+偏移（大杯运行时 cupMinY≈-0.0665≠网格推的 -0.4272）；反算后逐 fillLevel 复算验证
21. 打包后洋红=运行时缺材质/Shader（非 32/64 位问题）：资源加载别写 #if UNITY_EDITOR；未引用又不在 Resources 的资产不进包；拿不到材质宁可不赋值也别赋 null
22. Editor+运行时一起 csc 验证的引用组合见【项目元信息】（2026-11-09 实测）
23. **AutoAttach 反查必须用「直接子节点」特征**（2026-11-09）：递归查找会把组件挂到父级容器（前制作台子树里也有杯位）；
    机器从父级移出后挂错对象（TeaMachine 挂到加热机 → 找不到出料口 → 不出液）。TeaMachine 还跳过有「杯位左/右」者
