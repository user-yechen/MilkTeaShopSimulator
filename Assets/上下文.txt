【历史经验教训】
1. 场景中文 YAML 存 \uXXXX，grep 搜不到，要 python unicode_escape 解码
2. ApplyScaleTool 累积变换用 Matrix4x4，别 Quaternion+Vector3 分开（非均匀缩放×旋转不可交换）
3. BoxCollider 无法表示旋转，近似用三轴向量长度换算 size
4. 地面检测先过滤 IsChildOf(transform) 的自身 Collider
5. 新节点未 Ctrl+S → 磁盘场景查不到（按名查找失败先怀疑没保存）
6. ParticleSystem Shape 局部旋转×LocalSimulationSpace：SetParent 继承 nozzle 旋转会错位；修：只拷 position
7. Cone 默认 local+Z 发射，绕 X 轴 +90° 向下落水，-90° 向上喷泉
8. StartsWith 名字歧义："奶茶杯_中" 会匹配 "奶茶杯_中(Clone)"；模板用名「中奶茶杯」避开
9. m_LocalEulerAnglesHint 是 Editor 显示缓存，真实旋转看 m_LocalRotation 四元数
10. 重构原则：状态+行为下沉到设备组件，协调器只做「谁在近处+弹按钮+转发」
11. 设备 GameObject 名不可靠 → AutoAttach 用**直接子节点**特征反查（递归会挂到父级容器）
12. C# 元组解构：var (cup, scale) = TakeCup(...) 直接可用
13. JSON 存档：JsonUtility + persistentDataPath 即可；恢复放 Start 不放 Awake
14. UI 挂点优先用场景已有节点改内容，别 new 组件覆盖美术排版
15. 液面/包围盒：Renderer.bounds 是世界 AABB，旋转会膨胀 → 用网格本地包围盒角点换算
16. 手动微调的液体参数要反算：Y 缩放 sy→高×sy 斜率÷sy；位置写死绝对值，别用 cupMinY 推算
17. 打包后洋红=运行时缺材质/Shader：资源别写 #if UNITY_EDITOR；未引用又不在 Resources 的不进包；
   拿不到材质宁可不赋值也别赋 null
18. UGUI：anchor(0.5,1) 时 anchoredPosition +y 会出屏；可见性以 Game 视图/Canvas 尺寸算
19. 预制件变体不能手填 100100000 当根 GameObject 引用（会解析成 PrefabInstance，Instantiate 抛异常）
20. AutoAttach 必须用直接子节点特征；否则机器从父级移出后会挂错对象（TeaMachine 挂到加热机 → 不出液）

> 与具体脚本强相关的坑（AddComponent 顺序、同名「金额」、出料口自动创建、杯架 Y 镜像、
> 按钮统一入口等）已迁到《脚本接口》第 8 节，本文不再重复。
