# 美术与模型内容产线方案（多智能体 + 工具链）

> 2026-11-27　｜　适用：奶茶店模拟器（Unity 2022.3 / 移动端 / 低模风格）

---

## 0. 一句话结论

**不要先上「多智能体 + C站模型 + MCP」三件套。**
你项目的模型是 **12–1,692 三角面、单材质、贴图 ≤1.2MB** 的低模，这个量级用 **Blender 参数化脚本 + 批量导入** 最快；
智能体负责「写脚本、批量执行、渲染审查、Unity 接线」，不负责「审美判断」。
C站是 2D 图像模型站，产不出你要的 3D 模型；MCP 不是必需品，CLI 批处理更稳。

---

## 1. 项目现状与硬约束（实测）

| 指标 | 现状 | 说明 |
|---|---|---|
| 三角面 | 12 – 1,692（中位约 250） | 加热机 1692 最高，前台 24、前制作台lv1 12 |
| 材质 | 每个模型 1 个（最多 3 个） | 单材质 + 一张贴图是主流 |
| 贴图 | 8 KB – 1.16 MB，多为 512/1024 | 内嵌在 GLB |
| 网格 | 全部单网格（少数 2–3 个） | 无骨骼、无 LOD |
| 引擎 | Built-in 渲染管线，无 URP | 材质用 Standard + 自定义 Shader |
| 目标平台 | Android，minSdk 22 / target 35 | 低端机要控 DrawCall 与面数 |

**结论（2026-11-27 修订）：** AI 3D 默认输出 1–10 万面、拓扑偏乱，直接减到 1,500 面成本高。
但 Tripo 的 `face_limit` 参数可以**直出预算内面数**（实测 `-p face_limit=1500` 生效），
所以「复杂有机造型」可以走 Tripo，**简单方盒设备仍建议参数化建模**。详见 [3D资产管线-Tripo.md](../05-3D/3D资产管线-Tripo.md)。

## 2. 三条生产路线对比

| 路线 | 适合 | 单件耗时 | 风格一致性 | 成本 | 建议 |
|---|---|---|---|---|---|
| A. Blender 参数化脚本 + 手工微调 | 设备、杯子、货架、小料、装饰 | 0.5–3 h | 高（同一套脚本/色板） | 低 | **主力** |
| B. 买/下资产包（Quaternius、Kenney、Sketchfab） | 街景、路人变体、通用家具 | 0.2–1 h（改材质/减面） | 中（需统一材质） | 低–中 | **补充** |
| C. AI 图生 3D（Meshy/Tripo） | 复杂有机造型（角色、吉祥物） | 2–6 h（重拓扑+修） | 低 | 中 | 仅角色/概念阶段 |

**混合策略：** 设备与道具走 A；街景/杂项走 B；角色先用现有路人换色变体（改材质 + 换配饰），确有必要再试 C。

## 3. 多智能体分工（1 个编排 + 4 个角色）

| 角色 | 职责 | 输入 | 输出 | 验收标准 |
|---|---|---|---|---|
| **美术总监**（编排者/我） | 风格圣经、色板、比例、命名、验收 | 参考图、现有模型 | 《美术规范.md》、资产需求单、验收结论 | 每件资产有 spec，渲染图过审 |
| **模型师 A/B**（2 个并行） | Blender Python 参数化建模、UV、烘焙、导出 | 单件 spec JSON | `.glb` + 转台渲染图 + 尺寸报告 | 面数/尺寸/轴心/朝向达标 |
| **技术美术** | Unity 导入设置、材质、碰撞、Prefab、接线 | `.glb` + spec | Prefab、材质、场景接线 | 拖进场景即用，无紫材质 |
| **QA** | 批量校验、日志、性能、截图对比 | Prefab + 场景 | 报告（面数/DrawCall/异常） | 全部通过才合并 |

**并行原则：** 美术总监先锁规范 → 模型师 A/B 分批次并行 → 技术美术接一件验一件 → QA 汇总。
**不要**让 5 个 agent 同时自由发挥，会产出 5 种风格。

## 4. 资产合同（Asset Contract）

每件资产先写一份 spec（JSON），模型师只按 spec 做，QA 只按 spec 验：

```json
{
  "id": "topping_pearl",
  "name": "珍珠",
  "category": "小料",
  "triBudget": 200,
  "size": [0.06, 0.06, 0.06],
  "pivot": "bottom-center",
  "forward": "+Z",
  "materials": 1,
  "textureSize": 256,
  "collider": "none",
  "prefab": "Resources/预制件/小料/珍珠.prefab",
  "notes": "杯内小料，可用半球+位移贴图，颜色 #2B1A12"
}
```

**全局规范（所有资产必须遵守）**

- 单位：1 Unity 单位 = 1 米；导出 GLB，应用修改器
- 轴心：底部中心（Pivot = bottom center）；朝向 +Z（Unity 前）
- 命名：`类型_名称_变体`，如 `设备_奶茶机_lv2`、`装饰_招牌_01`、`小料_珍珠`
- 面数上限：小料/装饰 ≤300；杯子 ≤400；中型设备 ≤1,500；角色 ≤2,000
- 材质：1 个/模型；贴图 256–1024；颜色进色板，不写死
- 碰撞：设备用 BoxCollider 近似（旋转体用三轴包围盒），小料不加
- 禁止：多材质、透明叠层、超过 2K 贴图、未应用缩放

## 5. 工具链与命令

### Blender 无头批处理

```powershell
& D:\Blender\blender.exe -b -P Tools\Blender\build_prop.py -- `
    --spec Assets/Specs/topping_pearl.json `
    --out  Assets/模型/小料/珍珠.glb `
    --render Temp\review\珍珠.png
```

脚本职责：读 spec → 建/改网格 → UV → 材质 → 导出 GLB → 渲染 3 视图（正/侧/45°）→ 打印面数与尺寸。

### Unity 批量导入

```powershell
& D:\unity\2022.3.56f1c1\Editor\Unity.exe -batchmode -quit `
    -projectPath D:\UnityProject\milktea `
    -executeMethod ArtImportTool.ImportAll -logFile Build\art_import.log
```

职责：设置 ModelImporter（缩放、材质、读写）、生成 Prefab、补 Collider、写进 Resources/预制件 对应目录。

### 审查闭环（关键）

1. 模型师出 3 视图渲染图
2. 美术总监/我 `read_image` 看比例、剪影、颜色
3. QA 看面数/尺寸/轴心报告
4. 通过 → 技术美术接 Unity → QA 场景截图对比
5. 不通过 → 回模型师，附具体问题（不要只说"不好看"）

## 6. C站（Civitai）能做什么、不能做什么

| 能做 | 不能做 |
|---|---|
| 2D 概念图（店铺风格、角色设定） | 直接产出 3D 模型 |
| 饮品/小料图标（OrderBubble 用） | 保证多视角一致（同一角色转面会崩） |
| 贴图/花纹/招牌文字底图 | 低面数、干净拓扑 |
| UI 背景、宣传图 | 可直接进 Unity 的 GLB |

**注意**
- C站是 Stable Diffusion 大模型/LoRA 的集散地，本质是 2D 生图。
- 商用许可要看每个模型的 license（很多禁止商用或需授权）；生成图的版权归属在国内也有争议。
- 如果只是做图标：现有 `Resources/贴图/` 里的牛奶/茶图标风格已经很统一，**用 PS/Figma 画比生成更快**。
- 想要 3D 资产包：Quaternius、Kenney、Poly Pizza（免费/CC0）、Sketchfab（看许可）。

## 7. MCP：现状与建议

**现状（已查）**
- DSH 内核里有 `mcp` 插件包（cordis bundle），会话层支持 `mcpServers`。
- 但当前桌面 profile 只启用了 `dsh-base / dsh-web-app / token-monitor / usage-widget`，**没有启用 mcp**。
- 启用需要改 `~/.dsh/profiles/desktop/` 的配置并重启 DSH，再装对应服务端（BlenderMCP 插件 / UnityMCP 包）。

**建议**
- **批量生产不用 MCP。** Blender `-b -P` 和 Unity `-batchmode -executeMethod` 已经能覆盖 90%，可复现、可回滚、可进 CI。
- MCP 适合「实时交互」：让 agent 在你打开的 Blender 里改材质、摆场景、调灯光。这类操作反而不适合无人值守。
- 如果确实要试：先接 **BlenderMCP**（改材质/摆件最快见效），UnityMCP 次之。我可以帮你开，但要先确认 DSH 版本与插件兼容性。

## 8. 两周落地计划

| 时间 | 任务 | 产出 |
|---|---|---|
| D1 | 写《美术规范》+ 色板 + 资产清单 | 规范文档、20 件待做资产 spec |
| D2 | 写 Blender 模板脚本（杯子/设备外壳/小料/装饰四类） | `Tools/Blender/*.py`，能跑通一件 |
| D3–4 | 试点 3 件：珍珠、椰果、新品杯型 | GLB + 渲染图 + spec 验收 |
| D5 | 写 Unity `ArtImportTool`（导入/Prefab/Collider） | 3 件进场景可用 |
| D6–8 | 批量：6 款饮品图标 + 3 件装饰 + 2 个顾客变体 | 一批资产 |
| D9–10 | 技术美术接线（ShelfZone / MachineLevel / OrderBubble 图标） | 内容进玩法 |
| D11–12 | QA：面数/DrawCall/紫材质/尺寸回归 | 报告 + 修复 |

**试点先做「小料」**：面数低（≤200）、无骨骼、无碰撞、直接进杯子，是最快验证整条流水线的资产。

## 9. 成本与风险

| 风险 | 表现 | 对策 |
|---|---|---|
| 风格漂移 | 每件资产颜色/比例不一致 | 色板 + 参考板 + 统一脚本 |
| 面数失控 | 低端机掉帧 | spec 写死 triBudget，QA 卡 |
| 轴心/朝向错 | 进场景悬空/背对玩家 | 导出脚本统一处理，导入后自动校验 |
| 许可问题 | 商用被追责 | 只用 CC0/已购资产；AI 图查 license |
| 过度自动化 | agent 产出一堆不可用资产 | 每件必须过渲染审查，不合格打回 |
