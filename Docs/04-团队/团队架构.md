# 团队架构与协作约定

> 2026-11-27　｜　适用：1 人主控 + 多个 AI Agent 的独立游戏团队
> 目标：明确「谁负责什么、交付什么、怎么验收」，避免 Agent 产出不可用或风格漂移。

---

## 1. 现状

- **主控（你）**：制作人 + 策划 + 程序 + 技术美术 + 最终审美判断
- **AI Agent**：2D 美术、3D 管线、构建/QA 辅助
- **外部服务**：Tripo（图生 3D）、TripoSR（本地）、Blender（减面/渲染）
- **协作工具**：GitHub（代码/文档）、`Assets/上下文.txt`（项目记忆）、`Docs/`（规范）

> 现阶段不需要「招聘」，需要的是**把重复劳动交给 Agent、把判断留给人**。

## 3. Agent 清单

### 3.1 2D-UI Agent

- **职责**：按钮、面板、功能图标、三态、9-slice
- **输入**：`spec`（JSON，见 2D 美术手册）+ 色板
- **输出**：`ArtSource/2D/icons/*.svg` + `Assets/贴图/UI/*.png` + 预览图
- **工具**：`Tools/Art2D/make_ui_icon.py`（PIL/SVG）
- **限制**：不会「手绘」；复杂插画需外部 SD/ComfyUI
- **验收**：色板内取色、无描边、透明边距 ≥10%、三态齐全

### 3.2 2D-Product Agent

- **职责**：订单/商店用的杯、液体、小料图标
- **方法**：Blender 无头渲染现有 3D 杯模型，只换液体颜色/配料
- **输出**：`Assets/Resources/贴图/订单/*.png`（512²，透明）
- **验收**：与现有 4 张图标同角度、同光照、同构图

### 3.3 2D-QA Agent

- **职责**：色板偏差、alpha、尺寸、命名、联络表
- **输出**：`Temp/art_review/report.md` + `contact_sheet.png`
- **验收**：全过才允许合入

### 3.4 3D 模型 Agent（唯一模型产出）

- **职责**：所有 3D 模型的生产与验收；**2D → 3D 由 Tripo 负责**，减面/修整由 Blender 负责
- **输入**：spec（面数/尺寸/轴心）+ 3/4 参考图（白底、1024）
- **工具**：Tripo CLI（主，`npx -y tripo-cli`）→ `decimate_to_budget.py` → `render_views.py`
- **输出**：`ArtSource/3D/final/*.glb` + 三视角预览 + 面数/尺寸报告
- **不负责**：贴图与材质（美术 Agent）、3D→2D 图标（3转2 图标 Agent）
- **验收**：面数达标、单材质、轴心底边中心、+Z 朝前、无残留节点
- **手册**：[Agents/3D模型Agent.md](../06-Agents/3D模型Agent.md)

### 3.5 Build / QA Agent

- **职责**：一键出包、跑日志、查异常、性能采样
- **工具**：`Assets/Editor/BuildScript.cs`、`Build/build.log`
- **输出**：APK + 构建报告
- **验收**：`Build Finished, Result: Success`，安装可跑

### 3.6 3D → 2D 图标 Agent

- **职责**：把项目里的 3D 模型渲染成 2D 图标（订单/商店/UI），保证「图标 = 实物」
- **工具**：`Tools/Art2D/render_icon.py`（Blender 无头渲染）+ `Tools/Art2D/icon_post.py`（描边/阴影/居中）
- **输入**：模型路径 + spec（yaw/pitch/尺寸/描边）
- **输出**：512² 透明 PNG + 预览 + 渲染原图
- **验收**：logo 正向、与参考图标同角度、透明边距 ≥8%、描边 1–2 px
- **手册**：[Agents/3转2图标Agent.md](../06-Agents/3转2图标Agent.md)

### 3.7 文案 Agent

- **职责**：把用户写的大纲润色、拆条、产出可导入 Unity 的文案表（CSV）
- **输入**：文案大纲（`Docs/文案/大纲.md` 或对话里直接给）
- **输出**：`Assets/Resources/文案/文案表.csv` + key 变更说明 + 校验结果
- **工具**：菜单「奶茶店/文案/校验并生成 Key」、运行时 `GText.Get/Format`
- **验收**：校验 0 错误、key 唯一、字数不超限、占位符匹配
- **手册**：[Agents/文案Agent.md](../06-Agents/文案Agent.md)

### 3.8 音乐 Agent

- **职责**：BGM 作曲 / 编曲 / 导出 / Unity 音频接入规范
- **音色**：钢琴、合成器 Pad、木吉他、架子鼓（GM 音色表）
- **输入**：场景（白天 / 打烊 / 商店 / 教学）、情绪、时长、循环
- **工具**：`Tools/Music/make_bgm.py` + `specs/*.json` 生成 MIDI；DAW 试听与混音
- **输出**：MIDI + 和弦进行 + 编曲说明 + 混音参数；成品 OGG 44.1 kHz
- **验收**：循环无爆音、和弦正确、四层清晰、-16 LUFS
- **手册**：[Agents/音乐Agent.md](../06-Agents/音乐Agent.md)

## 4. 工作流（每个资产/功能都走）

```
需求（制作人）
  → 写 spec（策划/美术总监）
  → 生产（对应 Agent）
  → 预览/自检（Agent 按验收清单）
  → 评审（你或美术总监看渲染/截图）
  → 集成（技术美术接进 Unity）
  → QA（回归 + 性能）
  → 归档（提交 + 更新文档）
```

**Gate 规则**

| Gate | 不通过就退回 |
|---|---|
| G1 spec 完整 | 缺字段 → 退回需求方 |
| G2 自检通过 | 面数/色板/尺寸不符 → 退回生产者 |
| G3 评审通过 | 风格不符 → 退回并给具体修改项 |
| G4 集成通过 | 紫材质/悬空/穿模 → 退回技术美术 |
| G5 QA 通过 | 掉帧/报错 → 退回程序 |

**禁止**：跳过 spec 直接开工；跳过预览直接进 Unity；用「再好看点」当反馈。

## 5. 交接契约

### 5.1 资产 spec（必须）

```json
{
  "id": "topping_pearl",
  "name": "珍珠",
  "type": "3d",
  "triBudget": 200,
  "size": [0.06, 0.06, 0.06],
  "pivot": "bottom-center",
  "forward": "+Z",
  "materials": 1,
  "textureSize": 256,
  "deliverable": "Assets/模型/道具/珍珠.glb"
}
```

### 5.2 交付物清单

| 类型 | 必须带 |
|---|---|
| 2D | 源文件（SVG/PSD）+ PNG + 预览图 |
| 3D | GLB + 原始文件 + 面数/尺寸报告 + 预览渲染 |
| 代码 | 可编译 + 接口文档更新 + 提交流 |

### 5.3 命名

- 贴图：`UI_按钮_主.png`、`图标_金币.png`、`订单_大杯.png`
- 模型：`设备_奶茶机_lv2.glb`、`道具_珍珠.glb`
- 场景对象：保持现有中文名（大量脚本按名查找，改名会静默失效）

## 8. 能力缺口与建议

| 缺口 | 影响 | 建议 |
|---|---|---|
| 音频 | 成品感为零 | 先用商用素材包，后期找外包 |
| 动画 | 角色/设备动作僵硬 | 先程序动画（位移/旋转），关键动作再外包 |
| 2D 手绘 | 图标缺乏质感 | 接 ComfyUI/SD 或外包 3–5 张关键图 |
| 发行合规 | 无法上架 | 提前 6–12 个月启动版号/隐私 |
| 测试 | 回归靠手点 | 先写 20 条手工用例，再补 PlayMode 测试 |

---

## 9. 决策权

- **风格**：美术总监（你）一票否决
- **范围**：制作人（你）拍板，Agent 不自行加需求
- **技术选型**：程序建议，制作人确认
- **上线**：制作人 + QA 双签

> Agent 可以提建议，但不能改需求、不能改色板、不能改命名规范。
